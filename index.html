The loop

A review loop built for resistance.

One pass is useful. A second pass is where the first review gets tested instead of trusted.

01

Clean pass

Each round starts from the work itself, before the previous review gets a vote.

02

Counter-pass

The next review attacks both the original work and the last review’s weak spots.

03

Merge pressure

Confirmed issues survive. Weak findings die. New structural fixes move forward.

Use cases

Use it when “good enough” is not good enough.

If the work sounds convincing and the cost of being wrong matters, put it under pressure first.

AI answers Plans Prompts Procedures Code fixes Decision notes Proposals

Output shape

Not comments. Findings.

The output is designed to be checked, challenged, merged, or applied.

Break

The fallback depends on a condition that is never defined.

Evidence

The plan explains the success path, but never names the failure path.

Fix

Add a decision rule for the failure path before execution.

Ping-pong mode

Second opinions that do not just agree.

Chat A clean pressure pass
Chat B fresh pass + audit of A
Chat A checks what survived
Repeat until useful structural fixes stop appearing

Move the same work between two chats. Each round starts fresh, then attacks the previous review instead of inheriting it.

Boundaries

What it does not pretend to do.

  • It does not prove truth.
  • It does not replace judgment.
  • It does not remove model limits.
  • It is built to expose structural weakness, not polish language.
